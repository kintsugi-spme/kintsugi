## Perché

Il metodo del progetto è «prima prevedere, poi misurare»: il tag `m1` dimostra su Git che le previsioni sono state scritte **prima** di qualsiasi misura. Da questo momento la tabella delle previsioni (`docs/chapters/08-previsioni.tex`) non si modifica dopo aver visto una misura; se un valore cambia, lo si spiega nel diario e nei limiti.

## Comandi e configurazione

```bash
git checkout main && git pull
git tag -a m1 -m "M1: architettura e previsioni. Previsioni congelate: non si modificano dopo aver visto delle misure."
git push origin m1
gh issue close 11 --comment "..."
gh api -X PATCH repos/kintsugi-spme/kintsugi/milestones/1 -f state=closed
```

## Limiti dello strumento emersi

- **Il tag non è ancora protetto:** non esiste una regola sui tag `m*`; finché non c'è, chi ha i permessi può cancellarlo o spostarlo. Da creare in Settings → Rules → New tag ruleset (pattern `m*`, senza «Restrict creations»).
- **Manca la release con i PDF** del documento di architettura e della relazione di sintesi: da creare dal tag `m1`.
- Il tag è stato messo senza una conferma scritta di Gianmarco nel repository: va registrata qui o nella PR.
